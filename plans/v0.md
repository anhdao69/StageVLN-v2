# Technical Plan: Spatial Forcing for Qwen3.5 Vision-Language Navigation

## 1. Clear Goal

Implement the idea of **Spatial Forcing** for the Vision-Language Navigation task.

Use:

* **SpatialStack** as the main codebase.* **Qwen3.5-4B** as the VLN student model.* **VGGT** as a frozen spatial teacher during training.* **JanusVLN training data and navigation setup**.* **SpatialForcing** as the reference for the auxiliary feature-alignment loss.* No VGGT or spatial-feature fusion during inference.

The main goal is:

> Train Qwen3.5 to learn spatial and geometric information from VGGT through an auxiliary loss, while keeping the final navigation model independent of VGGT at inference.

The final model should predict:

```textMOVE_FORWARDTURN_LEFTTURN_RIGHTSTOP```

using the navigation instruction, historical observations, and current observation.

# 5. General Model Design

The system contains two branches during training.

## Student branch

```textInstruction + history frames + current frame↓Qwen3.5-4B↓Navigation action prediction↓Navigation cross-entropy```

## Teacher branch

```textCurrent frame↓Frozen VGGT↓Spatial teacher feature```

## Spatial Forcing branch

```textQwen intermediate current-frame feature↓Projector↓Compare with VGGT teacher feature↓Cosine alignment loss```

The total loss is:

L_{\text{navigation}}+\lambda_{\text{SF}} L_{\text{SF}}.]

VGGT features must not be added to Qwen features.

# 6. Important No-Fusion Rule

The first implementation is **Spatial Forcing loss only**.

Disable all SpatialStack geometry-fusion operations.

Do not:

```textadd VGGT features to Qwen visual featuresconcatenate VGGT and Qwen featuresuse geometry cross-attentioninject VGGT features into language layersuse VGGT output when predicting the action```

VGGT should affect training only through:

```textSpatial Forcing auxiliary loss```

Correct:

```textVGGT feature → loss calculation```

Incorrect:

```textVGGT feature → Qwen forward representation → action prediction```

This is required because VGGT will not exist during inference.

# 10. Spatial Grid Matching

The number of Qwen current-image tokens will probably differ from the number of VGGT patch tokens.

The coding agent should:

1. Determine the Qwen current-image grid:

```textH_qwen × W_qwen```

2. Determine the VGGT patch grid:

```textH_vggt × W_vggt```

3. Reshape VGGT tokens into the VGGT spatial grid.

4. Resize the VGGT grid to:

```textH_qwen × W_qwen```

5. Flatten it back into tokens.

The final shapes must match:

```textstudent:[N, D_qwen]

teacher:[N, D_vggt]```

Use the existing SpatialStack spatial resize or pooling logic where possible.

Do not resize a flattened token sequence directly. Reshape it into a 2D spatial grid first.

# 12. Spatial Forcing Loss

Normalize the projected student feature and frozen teacher feature:

```pythonstudent = normalize(projected_student)teacher = normalize(teacher_feature.detach())```

Calculate position-wise cosine loss:

```pythonsf_loss = 1 - cosine_similarity(student, teacher)sf_loss = sf_loss.mean()```

Calculate the final loss:

```pythontotal_loss = navigation_loss + sf_loss_weight * sf_loss```

Use:

```textsf_loss_weight = 0.3```

For the first run, a loss-weight warm-up is optional. Simplicity is more important than adding every feature immediately.

Log separately:

```textnavigation_lossspatial_forcing_losstotal_lossmean_cosine_similarity```
